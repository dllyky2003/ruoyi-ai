# 1. 输出要求（强制）
- 输出格式：YAML
- 根节点：caseTypeTemplates

  caseTypeTemplates:

# 2. 证据与判定口径（强制一致）
- 模板中所有核心“是否满足条件”的判定口径必须统一为：
  “窗口内确认（confirmedInWindow=true）”

- 对组合闭环规则（闭环同进同出、闭环必须同时满足的场景），必须：
  1）明确参与该闭环的证据项有哪些

- 模式B：不允许中文作为运行时证据键名
    - 运行时判定相关的“动作标识(actionId)/运行时字段键名”必须使用系统固定命名（英文或固定字符串）。
    - 但你仍要保留中文的“证据解释/规则解释/目标内容”等说明字段，使模板可读。
    - 若你缺少 actionId 清单，必须先生成“可读模板（中文概念名证据项）”，并在模板内部加入“待映射标注”（用中文说明需要替换为真实 actionId），同时保证整体结构仍然完整闭合，不得留空。

# 4. 时间窗与阶段（必须覆盖且结构闭合）
为该 caseTypeId 至少生成以下阶段概念（可按你现有结构命名，但必须包含内容且闭合）：
- 进入窗口/启动阶段（说明在窗口开始前后需确认的证据与处置）
- 窗口内完成阶段（说明在窗口内必须完成并用 confirmedInWindow=true 判定的证据）
- 窗口内复评阶段（说明窗口内复评完成的证据与判定）
- 结束/交接闭环阶段（说明交接信息完整与闭环完成的证据与判定）

每个阶段都必须包含：
- 阶段目标（中文）
- 阶段内需要确认的证据项清单（逐条列出）
- 阶段判定口径（统一以窗口内确认为准）
- 该阶段涉及的处置/监护要点（用中文解释，并与证据项对应）

# 5. 证据链建模（必须覆盖，且不要只列大类）
证据链至少要覆盖以下链路（可根据具体 caseType 调整数量与措辞，但必须体现闭环）：
- 诊断与证据确认链路
    - 例如：心电图解读确认、风险分层确认（按案例类型替换为对应中文证据项）
- 治疗与计划链路
    - 例如：抗栓/抗血小板计划确认（必要时可加入“适应证条件/条件性必做”说明）
- 监护与处置链路
    - 例如：血流动力学监护启动/确认
- 症状管理与支持链路
    - 例如：镇痛/供氧（必须以“条件性必做或可选解释”的方式写进规则，见第6部分）
- 沟通、转运与升级链路
    - 例如：转运目的地选择确认、ED通知完成确认、交接信息完整确认
- 复评与记录链路
    - 例如：窗口内复评完成确认、记录与闭环完成确认

对每条证据项都必须给出：
- 证据项名称（中文）
- 判定口径（窗口内确认 confirmedInWindow=true）
- 该证据项在闭环中的角色（简述即可，但要明确其作用）

# 6. 镇痛/供氧评分口径（必须写入模板，并给出判定策略）
模板里必须明确镇痛/供氧的评分策略，且写清楚“何时必做、何时可选或允许缺失”。
你必须从以下两种策略中选择一种并执行（由输入指定；若未指定，默认使用策略2）：

策略1：必做口径
- 若存在指征或需要满足的条件，则镇痛/供氧相关证据项必须在窗口内完成并满足 confirmedInWindow=true；否则判定为未完成。

策略2：条件性/可选解释口径（默认）
- 给出明确触发条件（例如：症状强度、氧合目标、风险分层等，以中文描述）
- 若触发条件满足，则视为必做并要求 confirmedInWindow=true
- 若触发条件不满足，则允许不做，但必须在模板中提供“可选解释/理由证据项”的结构（同样可用窗口内确认口径描述该解释已完成）

    - 同时满足 => 判定“转运交接闭环完成”

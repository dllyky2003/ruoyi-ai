1) 总体实体与 ER 关系（概览）
   主链路

case (1) — (N) case_version
case_version (N) — (1) case_type_template（案例版本基于某个“案例类型模板”版本；允许后续覆写）
case_version (1) — (N) case_event（关键事件时间线）
case_version (1) — (N) case_scoring_item（评分项）
case_version (1) — (N) rule_set（命中/路由规则集合，包含 AND/OR 树与优先级）
case_event (N) — (M) resource（事件关联资源：音频/图片/文案等）
模板链路（用于复用与从模板生成）

case_type (1) — (N) case_type_template
case_type_template (1) — (N) template_event
case_type_template (1) — (N) template_scoring_item
template_event 可挂模板资源；template_scoring_item 可带模板评分结构
可追溯映射（用于“从模板生成后仍可定位来源”）

case_event.template_event_id 可空：用于标识该事件是否来自模板
case_scoring_item.template_scoring_item_id 可空：用于标识该评分项是否来自模板
2) 表结构清单（字段名 + 类型 + 约束 + 说明；标注 必须/可选/派生）
   记号：[必填] / [可选] / [派生]
   类型示例：uuid、varchar、text、jsonb、int、smallint、boolean、timestamptz、timestamp。

2.1 案例基础：Case 与版本（满足“版本、适用指南、难度、标签、叙事/情景、时间线”等）
case
case_id uuid PK [必填]
case_code varchar(64) UNIQUE [必填]（内部唯一编码，如 preacls_iv_01）
title varchar(200) [必填]
summary text [可选]（后台列表摘要）
case_type_id uuid FK -> case_type [必填]（案例归类）
created_at timestamptz DEFAULT now() [必填]
updated_at timestamptz [派生/维护]（由应用写入或触发器维护）
is_archived boolean DEFAULT false [必填]
case_version
case_version_id uuid PK [必填]
case_id uuid FK -> case [必填]
version_no int CHECK(version_no>0) [必填]
status varchar(20) CHECK(status in ('draft','review','published','archived')) [必填]
case_type_template_id uuid FK -> case_type_template [必填]（该版本所基于模板版本）
difficulty_level smallint CHECK(1<=difficulty_level<=5) [必填]
difficulty_label varchar(50) [可选]（如“入门/进阶/挑战”）
applicable_guideline_scope jsonb [可选]（如“成人/儿科/现场环境限制”等补充口径）
narrative_scene jsonb [必填]（叙事/情景结构化内容：人物、场地、主诉、关键变量等）
timeline_format varchar(20) CHECK in ('relative_seconds','absolute_timestamp') [必填]
timeline_start_reference jsonb [可选]（若 relative：如 T0=呼救/到达/首评；若 absolute：指定起点规则）
created_at timestamptz [必填]
published_at timestamptz [可选]
ui_snapshot_hash varchar(64) [派生]（用于判断前端渲染差异/缓存失效，可选实现）
UNIQUE(case_id,version_no)
说明：

“叙事/情景”强烈建议用 jsonb 承载可扩展字段（避免频繁改表）。
时间线用 case_event 进一步结构化。
guideline_version
guideline_version_id uuid PK [必填]
guideline_name varchar(100) [必填]（如“ACLS Guidelines”）
year int [必填]
region varchar(50) [可选]（如 AHA/ILCOR 等口径）
version_tag varchar(30) [可选]（如 2020/2023 等更细粒度）
UNIQUE(guideline_name,year,region,version_tag)
case_version_guideline
case_version_id uuid FK -> case_version [必填]
guideline_version_id uuid FK -> guideline_version [必填]
is_primary boolean DEFAULT false [可选]
PK(case_version_id,guideline_version_id)

2.3 案例类型模板（caseTypeId → Template 的核心）
case_type
case_type_id uuid PK [必填]
case_type_code varchar(64) UNIQUE [必填]（如 preacls_suspected_cardiac_arrest）
name varchar(100) [必填]
description text [可选]
case_type_template
case_type_template_id uuid PK [必填]

5) 命中/路由规则（rules）建模：条件、AND/OR、优先级、命中结果与可解释性（reason）
   这里建议把“路由规则”做成规则集合 rule_set，每个 rule_set 由多条 routing_rule 组成；每条规则内部用条件组树表达 AND/OR（优先级用“规则优先级 + 同层组的执行/展示顺序”共同满足）。

5.1 规则集合（Rule Set）
rule_set
rule_set_id uuid PK [必填]
case_version_id uuid FK -> case_version [可选]（实例级规则）
template_rule_set_id uuid FK -> template_rule_set [可选]（如你也希望模板自带路由；题目未强制但建议）
scope_type varchar(30) CHECK in ('event_routing','scoring_routing','ui_visibility','remediation') [必填]
scope_event_id uuid FK -> case_event [可选/必填取决于 scope_type]（例如从某事件出发的路由）
name varchar(200) [必填]
description text [可选]
evaluation_mode varchar(20) CHECK in ('first_match','all_match','highest_priority') [必填]
created_at timestamptz [必填]
5.2 规则（Rule）：带优先级与命中结果（含 reason）
routing_rule
routing_rule_id uuid PK [必填]
rule_set_id uuid FK -> rule_set [必填]
rule_name varchar(200) [必填]
priority int DEFAULT 0 [必填]（满足“优先级”要求；同一 rule_set 中数值越大/越小由你定义）
is_active boolean DEFAULT true [必填]
result_type varchar(30) CHECK in ('next_event','jump_to_sequence','set_flag','show_remediation','end_case','score_adjust') [必填]
result_event_id uuid FK -> case_event [可选]（当 result_type='next_event' 等）
result_payload jsonb [可选]（如跳转目标、参数、提示文案变量替换）
reason jsonb [必填/建议必填]（可解释性核心：原因代码/模板/触发证据）
例如：{"reasonCode":"BP_LOW_AFTER_RHYTHM","message":"检测到...因此..."}
created_at timestamptz [必填]
“可解释性（reason）”建议采用结构化 reason，不仅存一段文本，还存可展示字段与原因码（用于审计/复盘/教学反馈）。

5.3 规则条件：条件组树（AND/OR）与条件叶子
routing_condition_group
routing_condition_group_id uuid PK [必填]
routing_rule_id uuid FK -> routing_rule [必填]
parent_group_id uuid FK -> routing_condition_group [可选]（构成树）
logic_op varchar(10) CHECK in ('AND','OR') [必填]（该组内部如何组合子节点）
group_order int DEFAULT 0 [可选]（用于“优先级/执行顺序”展示；逻辑仍由 AND/OR+树结构决定）
created_at timestamptz [必填]
routing_condition_leaf
routing_condition_leaf_id uuid PK [必填]
routing_condition_group_id uuid FK -> routing_condition_group [必填]
attribute_key varchar(100) [必填]（如 vitals.bp_systolic、rhythm.type、intervention.administered）
operator varchar(20) CHECK in ('eq','ne','gt','gte','lt','lte','in','not_in','contains','exists','regex_match','between') [必填]
value_jsonb jsonb [可选/必填取决于 operator]
evidence_hint jsonb [可选]（当命中时用于解释：来自哪条数据/哪次测量）
condition_order int DEFAULT 0 [可选]
created_at timestamptz [必填]
6) 规则与事件的关联（从“关键事件时间线”触发路由）
   你可以选择两种方式之一：

方案 A（推荐）：scope_event_id 直接落在 rule_set
rule_set.scope_type='event_routing'
rule_set.scope_event_id = case_event_id
这样就能在编辑器里：选择某个事件 → 配置它的 rule_set。

方案 B：中间表绑定（当一个事件挂多个 rule_set）
case_event_rule_set_link
case_event_id uuid FK -> case_event [必填]
rule_set_id uuid FK -> rule_set [必填]
routing_phase varchar(20) CHECK in ('on_enter','on_assess','on_action','on_exit') [可选/必填取决于你的触发点]
link_order int [可选]
PK(case_event_id,rule_set_id,routing_phase)
7) “派生字段”建议清单（满足评审/导出/解释）
   常见需要“派生”的字段（可用于后台校验、缓存或教学反馈，不一定落表；但你要求标注，这里给出建议）：

case_event.display_time（相对秒 → 前端展示时间）
存在于查询层或计算列；属于**[派生]**
case_version.ui_snapshot_hash（用于检测模板覆写导致的渲染差异）
[派生]
路由命中解释：运行时生成的 hit_conditions, matched_rule_id, final_reason_text
可用实时计算，或落入日志表（如果你需要审计）
例如 routing_evaluation_log（可选实现）中体现为**[派生/运行时]**

8) 最小可用的数据链（你实现时的落地顺序建议）
   为了工程上更快落地，你可以按依赖顺序建表/接口：

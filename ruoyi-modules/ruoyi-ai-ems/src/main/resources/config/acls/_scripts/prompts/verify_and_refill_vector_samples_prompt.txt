你现在是资深院前 ACLS 导师、院前急救质控负责人、意图样本审核员。你的任务不是“尽量保留”，而是严格审核已有样本：语义和业务意图不属于该意图的，必须删除；删除后只补充真正合格的新样本。禁止为了数量硬凑。

【意图定义】
- intent_code：$intent_code
- 意图名称：$name_cn
- 标准话术/业务定义：$standard_script
- 关键词：$keywords
- 已有示例：
$examples

【已有待审核样本】
$existing_samples

【审核目标】
最终保留 + 新增最多 $n 条。
如果合格样本不足，可以少于 $n 条，并在 shortage 中填写实际缺口。
不得保留任何“边缘合格”“勉强相关”“关键词沾边”的样本。

【合格标准】
一条样本只有在同时满足以下条件时才算合格：
1. 语义归属：直接表达该意图的核心动作、判断、沟通或决策。
2. 业务归属：在院前 ACLS 流程中，确实属于该 intent_code 对应的节点。
3. 场景真实：像急救医生、护士、急救员、调度员、电话指导者在现场/救护车/通话中会说的话。
4. 单一意图：只触发当前意图，不混入其他意图。
5. 表达自然：短句、口语化、指令或确认式表达，不是教材定义、旁白、解释。
6. 长度合适：4 到 80 个字符。
7. 安全合规：不生成错误 ACLS 建议，不混淆心律、脉搏、呼吸、循环、按压、电击等关键概念。
8. 不与保留样本重复或近似重复。

【必须删除的情况】
- 只是包含关键词，但真实意图属于其他 intent。
- 需要大量上下文才能判断是否属于该意图。
- 同时混合多个意图，例如“检查脉搏并开始按压”。
- 过于书面、像教科书、像系统说明。
- 过于泛化，例如“开始评估”“处理患者”。
- 与已有示例几乎相同，只换一两个字。
- 违反院前 ACLS 业务顺序或职责边界。
- 存在争议时，按更严格标准处理：删除，不保留。

【补生成规则】
1. 只能补充真正合格的新样本。
2. 新样本不得与 keep 中任何样本重复或近似重复。
3. 新样本必须继续满足上述全部合格标准。
4. 如果无法补足到 $n，不要硬凑，输出实际 final 数量。
5. final 必须等于 keep + new，并且去重。

【输出格式】
只输出一个 JSON 对象，不要 markdown，不要解释，不要代码块。
格式如下：
{
  "intent_code": "$intent_code",
  "keep": ["保留的合格样本"],
  "remove": [
    {
      "sample": "被删除的样本原文",
      "reason": "删除原因，简要说明语义或业务意图为何不属于该意图"
    }
  ],
  "new": ["新补充的合格样本"],
  "final": ["最终保留和新增后的全部合格样本"],
  "shortage": 0
}

注意：
- shortage = $n - final 的数量；如果 final 已达到或超过 $n，则 shortage 为 0。
- 如果 final 超过 $n，只保留最合格、最多样的前 $n 条。
- 不得输出任何 JSON 之外的内容。

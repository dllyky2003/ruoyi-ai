# 院前 ACLS 培训系统：状态机方案（精简实施版）

> **版本**：v2.0（精简实施版）  
> **适用范围**：院前 ACLS / megacode 模拟教学培训系统  
> **文档状态**：供技术方案评审与实施参考

---

## 1. 目的与适用范围

本方案为院前 ACLS/megacode 培训系统的状态机框架设计文档，服务于**模拟教学培训**场景。

### 1.1 核心目标

| 目标 | 说明 |
|------|------|
| **确定性** | 同一时刻多个转移条件满足时，系统稳定选择唯一路径，确保学员获得一致的模拟反馈 |
| **可审计** | 每次状态转移记录关键决策证据，支持导师复盘学员的临床路径 |
| **可配置** | 算法流程以配置文件表达（`_rules.yaml`、`_variables.json`），代码保持通用，指南更新时改配置不改代码 |
| **容错友好** | 配置错误在运行时抛出明确异常，配置人员能快速定位修复，不追求编译期静态完备校验 |

### 1.2 适用范围

- 以 `caseType` 为域的多层流程（如 `GENERAL_ACLS`、`TACHYCARDIA`、`CARDIAC_ARREST` 等子流程域）
- Guard 条件使用 `#变量名` 形式引用上下文变量（含基础变量与派生变量）

---

## 2. 总体架构

三个核心组件协同工作：

| 组件 | 职责 |
|------|------|
| **状态机引擎** | 维护 `current_state`，驱动事件求值，执行状态转移 |
| **Guard 求值器** | 解析 `#变量名` 表达式，在上下文变量集合中取值并计算布尔结果，决定哪些转移可触发 |
| **变量上下文** | 维护当前场景的所有事实变量及派生变量，按作用域分层存放 |

> **设计原则**：引擎不感知临床语义，所有临床逻辑以配置文件表达。ACLS 指南更新时，只需修改配置文件，引擎代码不变。

---

## 3. 状态与转移定义

### 3.1 状态表示

- 每个 caseType 维护 `current_state`（当前状态标识，如 `TACHY_ASSESS`）
- 状态命名采用**自描述方式**（如 `STABLE_NARROW_TACHY`），便于导师直接阅读审计日志，无需额外注释字段
- 可选保留 `last_error` 用于错误追踪

### 3.2 转移（Transition）定义

每条转移包含以下字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `from_state` | string | ✅ | 源状态标识 |
| `to_state` | string | ✅ | 目标状态标识 |
| `priority` | int | ✅ | 数值越大优先级越高，用于冲突消解 |
| `guard` | string（SpEL） | ✅ | 条件表达式，如 `#心率 > 100 && #derived_qrs_width == '窄'` |
| `action` | string（可选） | ❌ | 执行后对过程标记变量的更新（如计数器 +1） |
| `deviation` | boolean | ❌ | 标记该路径是否为偏离指南的“试错路径”，默认 `false` |

**配置示例（_rules.yaml）：**

```yaml
transitions:
  - from: "TACHY_ASSESS"
    to: "STABLE_NARROW"
    guard: "#心率 > 100 && #derived_qrs_width == '窄' && #收缩压 >= 90"
    priority: 10
    deviation: false

  # 偏差路径：学员误判——血压已 < 90 但仍选稳定通路
  - from: "TACHY_ASSESS"
    to: "STABLE_NARROW"
    guard: "#心率 > 100 && #derived_qrs_width == '窄' && #收缩压 < 90"
    priority: 5
    deviation: true
